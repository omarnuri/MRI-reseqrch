# Запуск в Google Colab — пошагово

Рассчитано на Colab Pro с A100. Весь тяжёлый трафик и вычисления — в Colab;
с твоей машины ничего большого не уходит.

---

## Шаг 0. Отправить ветку на GitHub (один раз, с локальной машины)

Ноутбук в Colab забирает код из GitHub, поэтому ветка должна быть на сервере.

```bash
git -C ~/Desktop/mri-spine push -u origin qa/2026-07-refactor
```

Проверить, что ветка появилась: она должна быть видна в списке ветвей репозитория.

---

## Шаг 1. Настроить среду выполнения

1. Открыть [colab.research.google.com](https://colab.research.google.com).
2. **File → Open notebook → GitHub**, вставить `omarnuri/MRI-reseqrch`, в выпадающем
   списке ветвей выбрать `qa/2026-07-refactor`, открыть
   `notebooks/colab_pipeline.ipynb`.
   *(Прямая ссылка вида `colab.research.google.com/github/...` со слешем в имени
   ветки разбирается неоднозначно — через диалог надёжнее.)*
3. **Runtime → Change runtime type → A100 GPU**. Если доступен переключатель
   **High-RAM** — включить.
4. **Runtime → Run all** не использовать. Ячейки запускаются по очереди, потому что
   вторая из них ставит окружение и её результат надо увидеть.

---

## Шаг 2. Ячейка 1 — Drive, кэш весов, исходники

Поля:

| Поле | Значение |
|---|---|
| `DRIVE_ROOT` | `/content/drive/MyDrive` |
| `CACHE_DIR` | `/content/drive/MyDrive/spinelab-cache` |
| `BRANCH` | `qa/2026-07-refactor` |
| `MOUNT_DRIVE` | ✔ |

Запустить, разрешить доступ к Drive во всплывающем окне.

**Что должно напечататься:** путь к исходникам с коротким SHA коммита и строки
`cached spineps 0.00 GB` и т.п. — при первом запуске нули, это нормально. Кэш
заполнится на шаге 4 и на следующих запусках уже не будет качаться.

---

## Шаг 3. Ячейка 2 — окружение

Поля: `INSTALL_SEGMENTATION` ✔, `FORCE_REINSTALL` ✗.

Первый запуск ~5–8 минут (nnU-Net, SPINEPS, TotalSpineSeg, TotalSegmentator,
SimpleITK). Ячейка идемпотентна: повторный запуск в той же сессии ничего не ставит.
Ядро **не** перезапускается принудительно.

**Что должно напечататься:**

```
versions:
  torch              2.x
  nnunetv2           2.8.x
  spineps            2.0.0
  totalspineseg      2026xxxx
  totalsegmentator   2.16.x

GPU: NVIDIA A100-SXM4-40GB (40 GB)
  Хватает на профиль QUALITY в ячейке 3
```

Если какая-то строка `NOT IMPORTABLE` — поставить `FORCE_REINSTALL` ✔, запустить
снова, затем **Runtime → Restart session** один раз и повторить ячейки 1–2.

## Шаг 4. Быстрая проверка данных (необязательно, 10 секунд)

Прежде чем тратить GPU, посмотреть, что в исследовании. В новой ячейке:

```bash
!python -m spinelab inspect --dicom "$DICOM_PATH"
```

(либо подставить путь строкой). Печатает таблицу серий и вывод о том, на какие
вопросы это исследование в принципе может ответить.

## Шаг 5. Ячейка 3 — запуск пайплайна

Поля:

| Поле | Значение | Зачем |
|---|---|---|
| `DICOM_PATH` | ссылка на архив или путь в Drive | см. ниже |
| `SUBJECT_ID` | `anon` | попадает в отчёт вместо ФИО |
| `STAGES` | `all` | все 15 этапов |
| `FORCE` | пусто | заполняется только при пересчёте |
| `QUALITY` | ✔ | вторая независимая модель позвонков |
| `TTA_MIRROR` | ✔ | проверка устойчивости лево/право |
| `SHOW_PHI_AUDIT` | ✔ | что за идентифицирующие данные в заголовках |

Про `DICOM_PATH`: пока репозиторий публичный, можно указать прямую ссылку на архив —
Colab скачает его сам за секунды, ничего загружать не нужно. После того как
репозиторий станет приватным (это стоит сделать, `docs/PRIVACY.md`), ссылка
перестанет работать: тогда положить архив в Drive и указать путь вида
`/content/drive/MyDrive/mri/study.zip`.

**Ожидаемое время на A100, первый прогон:** 25–45 минут, из которых большая часть —
разовая загрузка весов (~5–7 ГБ) в кэш на Drive. Повторные прогоны 10–20 минут.

**Порядок этапов и что должно быть видно:**

```
[ingest           ] OK      — сколько серий найдено
[spineps          ] OK      — маски позвонков и задних элементов
[totalspineseg    ] OK      — мозг, канал, диски
[totalsegmentator ] OK      — мышцы
[register         ] OK      — сдвиг/поворот для fatsat и axial
[fatsat_qc        ] OK/PARTIAL — подавление жира подтверждено или нет
[crosscheck       ] OK/PARTIAL — согласие двух моделей по уровням
[facets_axial     ] OK      — фасеточные суставы по уровням
[geometry ... report] OK
```

`SKIP` с внятной причиной — это не ошибка, а сообщение об ограничении данных.
`FAIL` — это ошибка, и её текст надо принести мне.

## Шаг 6. Ячейка 5 — диагностика (это и надо присылать)

Печатает всё, что нужно для разбора на расстоянии: окружение (версии всех
инструментов, GPU, SHA исходников), таблицу этапов с длительностями, все внешние
команды с кодами возврата, зафиксированные проблемы, ключевые числа и хвост лога.
Логи копируются в Drive.

Та же команда локально:

```bash
python -m spinelab diagnose --work /content/spine_work --numbers
```

Пайплайн пишет по ходу дела два файла в `results/`:

* `run.log` — построчный лог с отметками времени;
* `run.jsonl` — по одному JSON-событию на строку (`stage_start`, `stage_end`,
  `command` с кодом возврата и хвостами stdout/stderr, `problem`, `run_aborted`).

Оба пишутся немедленно, а не в конце: сессия, умершая на середине, всё равно
оставляет всё до этого места.

## Шаг 7. Ячейка 4 — отчёт

`COPY_TO_DRIVE` ✔, `DRIVE_RESULTS_DIR` = `/content/drive/MyDrive/spinelab-results`.

Отчёт откроется тут же и скопируется в Drive (только HTML/JSON/PNG, промежуточные
NIfTI не копируются — они большие).

## Если соединение оборвалось

Просто запустить ячейку 3 снова. Выполненные этапы читаются из
`results/stages/*.json` и пропускаются, прогон продолжится с места обрыва. Если
Colab потерял и виртуальную машину — ячейки 1–2, потом 3; веса возьмутся из кэша на
Drive.

Пересчитать конкретный этап: `FORCE` = `marrow,posterior` (через запятую).

---

## Что смотреть в отчёте первым

1. **Контроль сегментации** — картинка с контурами. Если контуры не совпадают с
   позвонками, все числа ниже недействительны, и дальше читать незачем.
2. **Работает ли подавление жира** — если нет, вся ветка про отёк аннулируется,
   и в отчёте это будет написано прямо.
3. **Устойчивость определения стороны** (зеркальная TTA) — если неустойчиво, любые
   сравнения лево/право в этом прогоне читать нельзя.
4. **Согласие двух моделей по уровням** — какие уровни размечены надёжно.
5. И только потом — измерения: фасеточные суставы по уровням, геометрия, мышцы,
   канал, диски.

Такой порядок не случаен: сначала проверки, которые могут обесценить всё
остальное.

## Локально (без Colab)

На RTX 3050 Ti с 4 ГБ VRAM пайплайн запускается, но профиль `quality` включать не
надо:

```bash
python -m spinelab run --dicom ~/Desktop/mri-spine-data/study.zip --cache ~/spinelab-cache
```

Тесты, которым не нужны ни GPU, ни данные:

```bash
python -m pytest -q
```
